## Problem

attune logs through `slog` behind a `TraceIDHandler` that auto-injects
`trace_id`/`span_id` (`internal/observability/slog.go`), and wraps outbound HTTP
with `otelhttp`. Three mistakes silently break this telemetry and are caught by
neither `go vet` nor golangci-lint:

1. **non-context slog calls** — `slog.Info(…)` instead of `slog.InfoContext(ctx, …)`
   → the handler never sees a span → no trace correlation.
2. **business field collides with an OTel auto-injected key** — e.g. a hand-written
   `"trace_id"` / `"span_id"` → duplicate/ambiguous fields in the log backend.
3. **`&http.Client{…}` without an otelhttp Transport** → no outbound spans → APM
   topology loses the downstream node.

`CLAUDE.md` §1 lists these as gates (and §7 as conventions) but nothing enforced
them locally. The parent monorepo ships `bin/lint-slog.sh`; attune needs its own
trimmed copy, callable from the pre-commit hook (#3) and CI (#1).

## Goals

- A **≤ 1s**, dependency-free static check (plain bash + `grep` + `awk`; no
  `go build`, no `node_modules`).
- Catch the three rule classes; **document each rule + its fix** in the script header.
- **Warn-only by default** (the caller decides whether to block); **`--strict`** for
  CI hard-fail.
- **Per-line, per-rule** exemption syntax for sanctioned cases.
- Report **exactly** the three known Phase-1A warnings with **no false positives** —
  in particular, not the legitimate field-name constants in
  `internal/observability/attrs.go`.

## Non-goals

- **Fixing** the three current warnings — that's **#9**.
- **CI enforcement** (`--strict` in a job) — deferred until #9 clears the warnings,
  else CI goes red on every PR.
- **Banning direct `slog.*` in favour of `logext`** — that's **#48**; it will later
  redefine Rule 1. Today Rule 1 is deliberately narrow.
- **The pre-commit hook itself** — that's **#3**.
- **AST-level accuracy** — a grep linter can't follow const indirection or
  string-built URLs; that's an accepted limitation (see Risks).

## Proposal

### Detection (validated against all 88 tracked `.go` files)

| Rule | Match | Current findings |
|---|---|---|
| **rule-1** | `slog\.(Debug\|Info\|Warn\|Error)\(` — the non-`Context` variants only (`Info(` ≠ `InfoContext(`) | **0** |
| **rule-2** | `"(trace_id\|span_id\|service\.name\|http\.method\|http\.route\|http\.status_code)"\s*,` — the reserved name **as a structured key** (trailing comma); this excludes `const AttrTraceID = "trace_id"` (no comma) | **2** — `slog.go:32,33` |
| **rule-3** | brace-aware `awk` scan of each `&http.Client{…}` literal; warn if the block has no `Transport:` / `otelhttp.NewTransport` | **1** — `openai_backend.go:51` |

Fixes (echoed in the script header): rule-1 → `slog.InfoContext(ctx, …)` /
`logext.Infof(ctx, …)`; rule-2 → drop the manual key or use the non-colliding
`attrs.go` constants; rule-3 → `Transport: otelhttp.NewTransport(http.DefaultTransport)`.

### Mechanics

- File discovery: `git ls-files '*.go'` (tracked, vendor-free) via a `while`-read
  loop (**not** `mapfile` — macOS stock bash is 3.2).
- **Exemption**: append `// lint-slog:allow rule-N` to the offending line; it
  suppresses only that rule on that line.
- **Exit contract**: no args → report, **always exit 0** (caller blocks); `--strict`
  + ≥1 finding → **exit 1**; usage error / not a git tree → exit 2.

## Alternatives considered

- **`go/analysis` vet analyzer or a golangci-lint custom linter** — AST-accurate
  (would follow the `AttrTraceID` const and handle multi-line literals natively),
  but needs a Go module + compile step, runs slower, and diverges from the parent's
  bash tool. *Rejected* — heavier than a 30s pre-commit gate warrants; revisit if
  false positives ever bite.
- **grep-only Rule 3 (no awk)** — simpler, but a multi-line `&http.Client{…}` with
  `Transport` on a later line would false-positive. *Rejected* for the brace-aware awk.
- **Pre-exempting `slog.go:32-33`** (the canonical injector) — *Rejected*: #4 must
  *report* them (acceptance criterion); #9 owns the fix / exemption decision.

## Risks / tradeoffs

- **Const indirection is invisible** — `slog.InfoContext(ctx, msg, observability.AttrTraceID, v)`
  won't trip rule-2 (only string literals match). Acceptable: literal misuse is the
  common case, and the constant is the sanctioned path.
- **Rule 1 is narrow** — structured `slog.*Context` is allowed by design today; #48
  may tighten it to a logext-only facade.
- **bash 3.2** — avoided `mapfile` and other 4.x-isms so the pre-commit path works on
  stock macOS.
- **String-literal / block-comment false positives** — pure `//` comment lines are
  skipped (line-start–anchored, URL-safe), but a reserved token inside a string
  literal or a `/* … */` block can still match. None exist today; the exemption
  marker is the escape hatch.

### Isolated e2e harness — **36 assertions, 36 pass / 0 fail**

A throwaway git repo with 31 fixture files (positives, negatives, exemptions,
multi-line literals, comment lines, false-positive/negative traps); the real
script run against it.

- **MUST-catch (11):** all four non-context `slog.*`; `trace_id` / `span_id` / dotted
  `http.method` keys; single-line, multi-line, value-form, and **trailing-comment**
  `http.Client` without Transport.
- **MUST-skip (14):** `*Context` calls; all three exemptions; `const … = "trace_id"`;
  underscore business fields (`http_method` / `user_id`); `Transport`-bearing clients
  (single-line, multi-line, and **nested-func** literal); struct field `*http.Client`;
  **pure `//` comment lines** for all three rules.
- **Exit matrix:** findings→`0` / findings+`--strict`→`1` / clean→`0` / clean+`--strict`→`0` /
  unknown-arg→`2` / git-repo-no-`.go`→`2` / non-git→`2`. ✅
- **Misc:** runs from a subdirectory; `--help`; ANSI-free non-TTY output;
  tracked-but-deleted file → no stderr leak.

### Hardening: comment-line false positives suppressed

A finding on a **pure `//` comment line** (after indentation) is dropped, for all
three rules. The check is **anchored at line start** and never strips a mid-line
`//`, so `"http://…"` inside a string literal is untouched and trailing exemption
comments on real-code lines still work (both verified in the harness).

### Residual limitations (empirically probed; none occur in the current tree)

The per-line exemption is the escape hatch for these:

| Probe | Behavior |
|---|---|
| reserved token inside a **string literal** or `/* block comment */` | false-positive (caught) |
| `[]string{"trace_id", …}` / `case "trace_id",` | false-positive (caught) |
| `logger.Info()` / `slog.Default().Warn()` (instance methods) | false-negative (missed) |
| `map{"trace_id": 1}` (colon-style key) | false-negative (missed) |
| `"trace_id, span_id"` as a single string | correctly **not** matched |

Eliminating the string-literal / block-comment cases needs a Go tokenizer (out of
scope per the grep+awk mandate); revisit via an AST analyzer if they ever bite.
